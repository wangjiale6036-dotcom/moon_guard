## 二、项目简介

MoonGuard 面向微服务、Serverless、边缘函数和配置中心中的动态 API 契约治理需求。开发者可以使用 MoonBit DSL 组合规则，也可以在运行时从 JSON 文档加载规则，从而把经常变化的业务校验逻辑从应用发版中解耦出来。

v0.3 在校验引擎和版本化规则注册表基础上新增 Compatibility Radar。它不仅回答“当前输入是否符合规则”，还对基线规则与候选规则执行结构化兼容性预检，对调用方提供的样本进行双版本影子回放，并根据显式阈值给出晋级、保留、回退或证据不足建议。满足策略时，候选版本可以通过带预期基线检查的接口安全激活；灰度阶段可使用跨后端一致的万分比稳定分桶选择校验规则版本。

项目采用无回调规则树和纯 MoonBit 核心实现，同一套代码在 Wasm、Wasm GC、JavaScript、Native 四种后端共享语义。解析深度、执行深度、规则访问量和错误数量均有预算限制，适合把外部规则作为不可信输入处理。

## 三、要解决的问题

传统 API 校验通常散落在路由、控制器与业务函数中。规则发生变化时，即使候选规则本身能够解析和执行，也仍然存在三类上线风险：

1. 新规则收紧边界，导致已上线客户端原本合法的请求被拒绝；
2. 新规则意外放宽安全约束，使原本应拒绝的输入被接受；
3. 新旧规则都拒绝请求，但错误路径或机器错误码漂移，破坏调用方诊断逻辑。

仅使用少量正向样例做发布检查无法完整表达这些风险。MoonGuard 将规则结构差异、回放行为差异和发布策略组合成可审查证据，让“规则能运行”提升为“规则变化可以解释、可以回放、可以按策略阻止晋级”。

## 四、已完成成果

### 4.1 动态规则校验引擎

- 支持 null、boolean、integer、number、string、array、object、const、enum；
- 支持字符串长度、前后缀、包含、安全通配符、白名单、黑名单、ASCII、非空白和 18 种内置格式；
- 支持数字开闭区间、倍数、整数、正负数和非零；
- 支持数组元素、元组前缀、长度、去重和 contains 计数；
- 支持对象必填/可选/弃用字段、附加字段、依赖、互斥组和至少一个字段组；
- 支持 allOf、anyOf、oneOf、noneOf、not、nullable、optional 和条件规则；
- 支持 JSON Pointer / 点路径、稳定错误码、严重级别、值预览开关和执行统计；
- 支持规则静态分析、良构检查、轮廓、优化、JSON 导入导出与往返验证；
- 支持批量、JSON 数组和 JSON Lines 校验及问题直方图。

### 4.2 版本化规则注册表

- 同一业务 channel 保存不可变顺序版本；
- 首个版本自动激活，后续版本显式激活；
- 支持语义重复拦截、版本绑定校验、前一版本回滚；
- 支持带正向样例门禁的候选发布；
- 支持带格式版本的 manifest 导出和全有或全无恢复。

### 4.3 Compatibility Radar

- `compare_rules`、`compare_rule_json`：比较基线规则与候选规则；
- `compare_versions`、`compare_with_active`：直接比较注册表版本；
- 输出 `BreakingImpact`、`RelaxingImpact`、`ReviewImpact`；
- 每项变化包含 JSON Pointer 路径、规则关键字和可读原因；
- 覆盖类型、字符串、数字、数组、对象、枚举、包装器与部分组合规则；
- 对 `oneOf`、`noneOf`、条件谓词等无法安全推断的关系保守进入 Review；
- 启发式分数用于人工分诊，不作为兼容率或安全概率。

### 4.4 双版本影子回放

- 同一批调用方样本同时运行基线规则和候选规则；
- 区分 `StableAccept`、`StableReject`、`CandidateRegression`、`CandidateRelaxation`、`DiagnosticShift`；
- 汇总回归数量、整数基点回归率、诊断漂移、截断证据和双方问题直方图；
- 可显式捕获影子样本中已观察到的回归/放宽输入，供机器复验；
- 默认关闭诊断值预览且不保存请求体，只在调用方显式开启时保存行为分歧样本。

### 4.5 策略评估与稳定候选分桶

- `RolloutPolicy` 使用样本数、回归数、回归基点、静态/动态放宽、诊断漂移、截断证据等阈值；
- 输出 `PromoteCandidate`、`HoldCandidate`、`RollbackCandidate`、`InsufficientEvidence`；
- `promote_if_safe` 只在策略通过、候选版本较新且激活指针仍匹配被评估基线时激活；
- `stable_rollout_bucket` 提供跨四后端一致的 0–10000 基点非加密稳定分桶；
- `validate_canary_json` 根据 routing key 选择基线或候选规则执行校验。

```text
           ▼

           │                     │
           ▼                     ▼

                       └─────────┬──────────┘
                                 ▼
                           发布策略评估
                    ┌────────────┼────────────┐
                    ▼            ▼            ▼

                                               │
 routing key ──> 确定性稳定分桶 ───────────────┘
```

## 六、创新点

1. **校验与契约演化使用同一规则模型。** 运行时校验、规则版本、静态变化路径和影子行为差异不需要维护多套互相漂移的描述。
2. **结构化预检与真实样本回放互补。** 静态层发现明确的收紧、放宽和未知关系；行为层用调用方样本补充可复验的实际差异。
3. **发布建议可解释、阈值可审查。** 每个非晋级结果保留明确原因，整数基点避免四后端浮点阈值差异。
4. **安全默认值。** 未知静态关系不当作兼容；默认策略不容忍回归、放宽、诊断漂移与截断证据；影子报告默认脱敏。
5. **跨后端确定性。** 规则执行、指标计算和稳定分桶均在 MoonBit 四种目标上使用同一实现。

## 八、能力边界与风险说明

- 静态兼容性预检只分析 MoonGuard 规则模型的输入接受行为，不是形式化等价证明；
- 复杂条件、否定及互斥组合关系可能进入 `ReviewImpact`，最终决策仍由策略和调用方负责；
- 回归见证来自调用方提供并显式允许保存的回放样本，不是自动合成的最小反例；
- 影子功能不采集生产流量，注册表也不是网络化配置中心；
- 稳定分桶只选择规则版本，不操作 API 网关、网络流量、应用部署或自动回滚；
- 项目不是完整 JSON Schema 2020-12 实现，不支持远程 `$ref`、正则表达式或 XML。
